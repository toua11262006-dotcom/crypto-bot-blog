自動売買ボットを24時間動かすために、海外取引所に資金を置きっぱなしにしている方は多いと思います。[取引所が破綻したらどうなるか](/blog/exchange-bankruptcy-risk/)は気にする人が多いテーマですが、実際にはそこまで至らなくても「口座が凍結された」「出金だけできなくなった」という事態のほうが、頻度としては起こりやすいと言われています。この記事では、口座凍結・出金制限がなぜ起きるのか、ボット運用者としてどう備えるかを一般論として整理します。

## 破綻とは別のリスクであることを理解する

まず整理しておきたいのは、口座凍結・出金制限は取引所の経営破綻とは性質が異なるという点です。破綻は「取引所そのものが資金を返せなくなる」話ですが、凍結・出金制限は取引所自体は正常に運営されていても、特定のアカウントや機能だけが一時的に止められる現象です。原因が取り除かれれば解除されることが多く、必ずしも資産が失われるわけではありません。ただし解除までの期間、ボットが資金にアクセスできなくなる点は実務上の大きな問題になります。

## 口座凍結・出金制限が起こる代表的なパターン

### 1. AML(マネーロンダリング対策)に基づく一時停止

取引所は法令上、疑わしい取引パターンを検知した場合に口座を一時停止する義務を負っています。ボットによる高頻度・大口の入出金や、短期間での複数取引所間の資金移動は、意図せずこうしたパターンに該当してしまうことがあります。

### 2. 本人確認(KYC)の再審査・追加要求

多くの海外取引所は、取引量や出金額が一定の水準を超えると追加のKYC書類提出を求めます。[MEXCでAPI自動売買を始める手順](/blog/mexc-api-bot-guide/)でも触れているとおり、本人確認は取引レベルに応じて段階的に要求される仕組みが一般的です。書類提出が遅れると、その間は出金機能が制限されることがあります。

### 3. 規制当局からの行政指導・地域制限

取引所の登録国や、ユーザーの居住国の規制動向によって、特定地域からのアクセスやサービス提供が制限されることがあります。これは個々のユーザーの行動とは無関係に発生しうるリスクです。

### 4. セキュリティインシデント発生時の予防的措置

取引所側でハッキングや不正アクセスの疑いが検知された場合、被害拡大を防ぐために、影響の有無にかかわらず広範囲のアカウントで一時的に出金が停止されることがあります。

※これらの制度・運用は取引所ごと、また時期によって変更されるため、具体的な基準や手続きは必ず各取引所の公式情報を確認してください。

## ボット側はどう振る舞うべきか

[取引所がダウンした時の障害対応](/blog/exchange-outage-failsafe/)では、API自体が応答しなくなるケースの設計を扱いました。口座凍結・出金制限はこれと少し性質が異なり、**APIは正常に応答するが、注文や出金の一部だけがエラーを返す**という形で現れることが多い点に注意が必要です。

具体的には、通常のネットワークエラーと区別して、次のようなレスポンスを検知できるようにしておくと安全側に倒しやすくなります。

```python
RESTRICTED_ERROR_KEYWORDS = ["restricted", "kyc", "compliance", "frozen"]

def is_account_restricted(error_message: str) -> bool:
    lowered = error_message.lower()
    return any(keyword in lowered for keyword in RESTRICTED_ERROR_KEYWORDS)

try:
    exchange.create_order(symbol, "market", "buy", amount)
except Exception as e:
    if is_account_restricted(str(e)):
        # 新規発注を停止し、既存ポジションの監視モードへ切り替える
        bot_state.enter_restricted_mode()
    else:
        raise
```

このように「アカウント制限らしきエラー」を通常の一時的エラーと切り分けて検知し、リトライを繰り返すのではなく新規発注を止める設計にしておくことが重要です。

## 事前にできる備え

- **KYCは早めに完了させておく**: 資金を増やしてから慌てて追加書類を提出する状況を避けられます
- **出金先アドレスをホワイトリスト登録しておく**: 制限解除後の出金がスムーズになる取引所が多くあります
- **資金を複数取引所に分散する**: [複数取引所対応ボットの設計](/blog/multi-exchange-bot-design/)で触れたとおり運用コストは増えますが、1つの取引所が制限を受けても資金全体が動けなくなる事態は避けられます
- **APIキーの権限を必要最小限にする**: 出金権限を持たせないなど、[APIキーの安全な管理](/blog/api-key-security/)の考え方は凍結リスクとは別の観点でも重要です
- **1取引所あたりの資金配分を抑える**: [ポジションサイズの計算式](/blog/position-sizing-formula/)の考え方と同様に、1箇所に資金を集中させないこと自体がリスク管理になります

## 制限を受けてしまったときの対応

制限に気づいたら、まずボットを止めて状況を確認することが優先です。取引所からの通知メールやアプリ内の通知を確認し、追加書類の提出が求められている場合は速やかに対応します。SNS上の噂や非公式情報を鵜呑みにせず、必ず取引所の公式サポート・公式サイトの情報を確認してください。判断に迷う場合は自己判断で動かず、公式サポートへの問い合わせを優先しましょう。

## まとめ

- 口座凍結・出金制限は取引所の破綻とは別のリスクで、破綻より発生頻度は高いと言われています
- AML対応、KYC再審査、規制当局の指導、セキュリティインシデントなどが主な発生パターンです
- ボット側は「アカウント制限らしきエラー」を通常のエラーと区別し、新規発注を止める設計にしておくことが重要です
- KYCの早期完了、出金先ホワイトリスト登録、複数取引所への分散、APIキー権限の最小化が事前にできる備えです
- 制限を受けた場合は自己判断で動かず、必ず取引所の公式情報・公式サポートを確認してください
