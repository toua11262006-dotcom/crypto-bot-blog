無期限先物(Perpetual Futures)でボットを動かしていると、損益計算の中に見覚えのない項目が出てくることがあります。それが「ファンディングレート」です。手数料にもスリッページにも分類されないこのコストは、仕組みを理解していないと「なぜか成績が思ったより悪い」という原因になりがちです。この記事では、ファンディングレートがなぜ発生し、どう計算され、ボット設計上どこに注意すべきかを一般論として整理します。

## ファンディングレートとは何か

[無期限先物の記事](/blog/perpetual-futures-basics/)で触れたとおり、無期限先物には満期がありません。満期がある先物であれば、期限が近づくほど契約価格は自然と現物価格に収束しますが、無期限先物にはその仕組みがありません。

そこで代わりに使われているのが、ロング(買い)とショート(売り)の間で定期的に資金を受け渡しする「ファンディングレート」という仕組みです。基本的な考え方は次のとおりです。

- 契約価格が現物価格より高い(ロングが優勢) → ロング保有者がショート保有者に支払う
- 契約価格が現物価格より低い(ショートが優勢) → ショート保有者がロング保有者に支払う

つまりファンディングレートは「必ず払うコスト」ではなく、市場の偏りに応じて**受け取る側にもなり得る**仕組みです。ポジションの方向と市場の状況によって、コストになるかリターンになるかが変わります。

## 計算の仕組み:一般的な考え方

取引所ごとに細部は異なりますが、多くの取引所では次の2つの要素を組み合わせてファンディングレートを決めています。

- **プレミアム指数**: 無期限先物の契約価格と現物(インデックス)価格の差。差が大きいほどファンディングレートも大きくなる方向に働きます
- **金利差の要素**: 2つの資産(多くの場合はベース資産とクオート資産)の金利差に相当する固定的な要素

多くの取引所では、この2要素を一定の計算式で合成し、さらに**上限・下限(キャップ)**を設けて極端な値にならないよう調整しています。計算式自体は取引所ごとに公開されていることが多いですが、細部や係数は変更されることがあるため、具体的な数値を前提にした設計をする場合は必ず利用する取引所の公式ドキュメントで最新の計算方法を確認してください。

## いつ・いくら発生するのか

ファンディングレートの受け渡しは、多くの取引所で**8時間ごと**(1日3回)というタイミングで設定されています。ただし取引所によっては1時間ごとなど、異なる頻度を採用しているケースもあります。

重要なのは、この支払いが**ポジションを保有している間、繰り返し発生し続ける**という点です。1回あたりの金額は小さく見えても、同じ方向のポジションを長期間持ち続けるボットでは累積コストが無視できない規模になることがあります。

支払額のおおまかな考え方は次のようになります。

```
支払い額 ≒ ポジションサイズ(契約価値) × ファンディングレート
```

レートが0.01%でも、ポジションサイズが大きい・保有期間が長いと、積み重なった際の影響は[取引コストが成績に与える影響の記事](/blog/trading-cost-impact-formula/)で扱ったスリッページや手数料と同様、看過できないコストになり得ます。

## ボット運用でなぜ重要なのか

ファンディングレートがボット設計に関わってくる場面はいくつかあります。

- **長期保有型のロングボット**: トレンドフォロー型やDCA的な考え方で無期限先物のロングを長期間持ち続ける設計の場合、ロング優勢の市場ではファンディングレートが継続的なコストとして積み上がります
- **グリッドボットでの偏り**: [レンジ設定の記事](/blog/grid-bot-range-setting/)で触れたように、グリッドボットは価格帯によってロング・ショートの比率が変わります。平均してどちらかに偏った建玉を持ちやすい設計の場合、その偏りの方向とファンディングレートの方向次第でコスト・リターンが変わります
- **成績評価への影響**: バックテストで現物ベースの損益を再現しても、実際に無期限先物で運用するとファンディングレートの分だけ実績がずれます。検証と実運用の差分要因の一つとして認識しておく必要があります

なお、「ファンディングレートを受け取る側に回れば得になる」という発想自体は理論的には成立しますが、それを狙った設計(いわゆる現物とのベーシス取引的な考え方)には別のリスク(清算・スプレッド・資金効率など)が伴います。[レバレッジと清算の記事](/blog/leverage-liquidation-basics/)で触れた清算の仕組みとあわせて、仕組みの一部分だけを見て判断しないことが大切です。

## ccxtでファンディングレートを確認する

ccxtの基本的な使い方は[ccxtの使い方まとめ](/blog/ccxt-cheatsheet/)を参照してください。対応している取引所であれば、現在のファンディングレートと過去の履歴を取得できます。

```python
import ccxt

exchange = ccxt.mexc()

symbol = 'BTC/USDT:USDT'  # 無期限先物のシンボル表記は取引所ごとに異なる

# 現在のファンディングレート
funding = exchange.fetch_funding_rate(symbol)
print('現在のレート:', funding['fundingRate'])
print('次回の支払い時刻:', funding['fundingDatetime'])

# 過去のファンディングレート履歴(対応取引所のみ)
history = exchange.fetch_funding_rate_history(symbol, limit=10)
for h in history:
    print(h['datetime'], h['fundingRate'])
```

取得できる項目名やメソッドの対応状況は取引所によって差があります。実際にコードを組む前に、使う取引所がccxtでどこまで対応しているかを必ず確認してください。

## 設計上の注意点

- **取引所間の差を前提にする**: 計算式・頻度・上限値は取引所ごとに異なり、同じ銘柄でも取引所によってレートが違うことがあります
- **バックテストに含めるかを意識する**: 現物データだけでバックテストしている場合、ファンディングレートのコストは反映されません。無期限先物での運用を前提にするなら、検証段階でこの差分を認識しておくべきです
- **異常値への備え**: 市場が大きく偏った際にはファンディングレートが一時的に大きくなることがあります。想定外のコストにならないよう、定期的に現在のレートを監視する仕組みを入れておくと安心です

※ファンディングレートの計算方法・支払い頻度・上限値は取引所の仕様変更によって変わることがあります。具体的な数値を使った判断をする前に、必ず利用する取引所の公式ドキュメントで最新情報を確認してください。

## まとめ

- ファンディングレートは、満期のない無期限先物で契約価格を現物価格に近づけるための資金受け渡しの仕組み
- ロング優勢ならロングが支払い、ショート優勢ならショートが支払う。受け取る側になることもある
- 多くの取引所で8時間ごとに発生し、ポジションを保有し続ける限り繰り返し発生する
- 長期保有型のボットやグリッドボットでは、累積するとコスト・リターンとして無視できない規模になることがある
- 計算式・頻度・上限値は取引所ごとに異なるため、具体的な設計には公式ドキュメントの確認が欠かせない

ファンディングレートは手数料やスリッページと違って「取引した瞬間」には見えにくいコストです。無期限先物でボットを運用する場合は、成績を評価するときにこの要素も含めて考える習慣をつけておくとよいでしょう。
